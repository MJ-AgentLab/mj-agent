## 1 适用范围与标识

先确定 Site 帮助读者理解什么主题、完成什么任务，再按“主题：用途”命名。主题应说明实际内容，用途应说明读者可以如何使用该 Site。

本规范适用于项目附属 Sites。Chainlit、LangGraph Studio 等产品运行界面的名称与部署环境不在本规范范围内。命名约定本身不授权创建、发布、更名或改变访问范围；具体动作遵循相关任务的授权。

| 概念 | 本项目含义 |
| --- | --- |
| 项目显示名 | 统一使用 `mj-agent` |
| 主题 | Site 的内容对象，例如“工具错误反馈” |
| 用途 | Site 为读者提供的任务，例如“机制解读”或“方案审阅” |
| slug | 平台网址中的短名，与完整 URL 分开维护 |
| 平台 Site ID | 平台返回的稳定身份标识；维护已有 Site 时使用原值 |
| 关联编号 | 实际文档或任务的编号，例如 `ADR-029`、`Issue #555`；用于关联内容 |

平台 Site ID、关联编号、显示名称和 slug 分别记录，不能相互推断。名称中的编号不表示对应决策或任务已批准、完成或通过审阅。

## 2 名称组成

### 2.1 各显示位置

| 对象 | 格式 | 示例 |
| --- | --- | --- |
| 后台管理名称 | `mj-agent｜主题：用途` | `mj-agent｜工具错误反馈：机制解读` |
| 浏览器标题 `<title>` | `主题：用途｜mj-agent` | `工具错误反馈：机制解读｜mj-agent` |
| 页面主标题 | `主题：用途` | `工具错误反馈：机制解读` |
| 项目内链接文字 | `主题：用途` | `工具错误反馈：机制解读` |
| 跨项目链接文字 | 完整管理名称 | `mj-agent｜工具错误反馈：机制解读` |
| slug | `mj-agent-<主题英文短名>-<用途>` | `mj-agent-tool-errors-explanation` |

后台名称先标项目归属；浏览器标题先标具体内容。显示文字默认中文，保留 SQL、ADR、LangGraph 等既定专业术语。分隔符统一使用全角 `｜` 和 `：`。

管理名称、浏览器标题、主标题和链接文字应表达同一主题与用途。链接文字说明目的地，避免只写“点击这里”或裸编号。页眉可以另行显示项目名，主标题仍按表中格式填写。

### 2.2 用途词

下表是 slug 用途部分的推荐词，不是封闭枚举。显示文字使用中文或既定专业术语；有其他实际用途时，选用清楚、稳定的英文短名并在维护记录中说明。

| 显示用途示例 | slug 推荐词 | 适用内容 |
| --- | --- | --- |
| 文档解读、机制解读 | `explanation` | 解释文档或机制的含义与关系 |
| 方案审阅 | `review` | 帮助读者检查方案并提出反馈 |
| 架构说明、架构概览 | `architecture` | 展示组件、职责和数据流 |
| 入门指南、操作指南 | `guide` | 支持读者完成具体操作 |
| 教学、教程 | `tutorial` | 按学习顺序讲解或练习 |
| 交互演示 | `demo` | 展示操作、机制或效果 |

同主题的不同用途可以分别建站，例如机制解读与方案审阅；两者应采用各自实际用途，不能仅为制造不同 slug 而改写名称。

### 2.3 文档、任务与阶段编号

Site 专门围绕某份文档或某个任务时，在主题前加入真实关联编号，例如 `mj-agent｜ADR-029 工具错误反馈：机制解读`。专门审阅某个 Issue 时采用 `mj-agent｜Issue #<实际编号> 主题：方案审阅`。

跨多份文档或任务的综合 Site 使用稳定主题，在维护记录或页面说明中关联来源，不把全部编号堆进名称。没有统一编号的文档按实际名称关联，不为命名新增编号体系。

阶段编号仅用于内容本身确有阶段结构的页面。mj-agent 的 SDD Stage、项目 Phase、文档编号各有原义，不为套用参考项目格式而重新编号，也不默认添加 `Stage 0`。

## 3 slug 与地址稳定性

### 3.1 新 Site 的 slug

新 Site 使用 `mj-agent-<主题英文短名>-<用途>`。主题和用途部分使用小写 ASCII 字母、数字与单连字符分隔词，整串无空格、下划线、连续连字符或首尾连字符；格式可按 `^mj-agent-[a-z0-9]+(?:-[a-z0-9]+)+$` 检查，语义仍需人工确认。

主题英文短名应描述实际内容。关联编号默认留在显示文字和维护记录；并存制品确需区分时，可进入主题部分，例如 `mj-agent-adr-029-tool-errors-explanation`。是否专属某份文档以实际内容为准，不能由编号后缀制造并存理由。

不以日期、修订版本或状态标签作为普通 slug 的区分后缀，例如 `-20261008`、`-v2`、`-draft`、`-final`、`-latest`；也不使用 `-new` 或无意义的 `-2` 区分制品。这不限制主题本身讨论版本管理、草案编写或发布流程。

slug 冲突时，先判断是否已有同用途 Site；若是同一制品则维护原 Site，若确需独立并存则用真实主题范围、目标或关联对象限定。主题、用途或并存关系仍不明确时，提供具体候选和差异，询问 Owner。

### 3.2 修订与既有地址

同用途修订沿用原平台 Site ID 和地址。日期、版本与状态写入维护记录或页面说明；平台版本号、文档版本和任务状态分别说明，不能相互替代。

已发布地址优先保持稳定。既有 slug 不符合新建格式时，先保留原地址，并在维护记录注明；本规范不要求批量重命名已发布地址。确需改名时，在具体任务中列明目标 Site、候选名称或 slug、已知链接和影响后按授权执行。

候选 slug 不等于已取得的网址。实际 URL 只采用平台返回值；地址变更后记录旧地址、新地址、变更日期和旧地址行为的实测范围。一次根地址跳转检查不能证明所有路径或未来更名都会跳转。

## 4 正反例与维护场景

以下均为命名候选与行为示例，不代表已创建或发布 Site，也不表示关联文档或任务已经验收。

### 4.1 正例与六类场景

| 场景 | 名称或处理 | slug 或核验要求 |
| --- | --- | --- |
| 普通主题 | `mj-agent｜工具错误反馈：机制解读` | `mj-agent-tool-errors-explanation` |
| 专属 ADR / Issue | `mj-agent｜ADR-029 工具错误反馈：机制解读`；`mj-agent｜Issue #555 批准删除范围：方案审阅` | 编号关联真实内容；slug 默认仍按主题和用途命名 |
| 同主题不同用途 | `mj-agent｜工具错误反馈：方案审阅` | `mj-agent-tool-errors-review`，与解读用途区分 |
| 同用途修订 | 机制解读增加新的说明或案例 | 保留原 Site ID 与地址；记录修订信息并逐处核对显示文字 |
| 名称冲突 | 若异步反馈确为独立主题，可用 `mj-agent｜异步工具错误反馈：机制解读` | `mj-agent-async-tool-errors-explanation`；仍以平台实际可用性为准 |
| 地址变更 | 按具体任务授权修改某个已发布 slug | 回读原 Site ID、新 slug 与实际 URL；同步已知链接，记录旧地址实测行为 |

### 4.2 反例

| 反例 | 问题 | 修正方向 |
| --- | --- | --- |
| `mj-agent｜ADR-029` | 只有编号，无法判断主题和用途 | 补充“工具错误反馈：机制解读” |
| `mj-agent｜最终版：演示` | 用状态代替主题 | 描述实际演示对象；修订状态另行记录 |
| `MJ_Agent-Tool_Errors-Demo` | 大写与下划线不符合 slug 格式 | `mj-agent-tool-errors-demo` |
| `mj-agent-tool-errors-explanation-v2` | 用修订版本区分同用途制品 | 复用原 Site 与地址，版本放维护记录 |
| `mj-agent-tool-errors-explanation-2` | 数字不能说明制品差异 | 查找原 Site；确需并存时增加真实主题限定 |
| 后台写“方案审阅”，页面主标题写“机制解读” | 各显示位置用途不一致 | 按实际用途同步名称、标题与链接文字 |
| 由候选 slug 拼出完整网址并登记为已发布 | 未取得平台实际地址 | 将 slug 标为候选，取得实际 URL 后再登记 |

## 5 创建与维护步骤

1. **确定内容**：读相关文档或任务，明确主题、用途、关联对象，以及创建新 Site 或维护已有 Site 的理由。专属文档或任务时确认实际编号。
2. **查找已有 Site**：先查任务已有记录和可用的平台信息；找到同用途制品时使用原平台 Site ID。查找范围不完整时如实记录，不能断言不存在。
3. **确定命名候选**：列出管理名称、浏览器标题、主标题、链接文字和候选 slug。维护已发布 Site 时优先保留地址；冲突按 §3.1 的真实范围限定处理。
4. **核对动作范围**：创建、修改源码、后台更名、slug 变更与发布按具体任务授权执行。仅编写命名方案时保留候选状态，不登记为实际执行结果。
5. **回读并同步**：执行后分别核对平台名称、Site ID、slug 和实际 URL，以及页面的浏览器标题、主标题与相关导航。地址变化时同步已知页面导航和本地链接，并记录旧地址实测行为。
6. **登记与完成检查**：把最小维护信息写入该任务的既有计划或证据记录，逐项填写实际核验范围和结果，再按 §6 完成自检。未取得的字段注明未知或未验证，不填猜测值。

最小维护信息可以使用现有表格或正文，不要求新建全局登记文件、frontmatter schema 或本地制品编号：

| 信息 | 登记内容 |
| --- | --- |
| 平台身份 | 实际平台 Site ID，原样保存 |
| 管理名称与 slug | 区分候选值和平台回读的实际值 |
| 实际 URL | 平台返回的地址；尚未取得时说明未验证 |
| 关联内容 | 文档路径、实际 ADR / Issue 编号或任务主题 |
| 核验时间 | 日期或带时区的时间；日期按项目使用的 Asia/Taipei |
| 核验范围与结果 | 后台、浏览器标题、主标题、导航分别记录实际检查情况 |
| 地址变更记录 | 有变更时补旧 / 新地址、变更日期、已知链接处理和旧地址实测范围 |

只保存维护所需的非秘密信息；访问凭据不属于命名记录。

## 6 作者自检清单

- [ ] 主题与用途清楚，显示名统一使用 `mj-agent`，默认中文并保留既定术语。
- [ ] 管理名称、浏览器标题、主标题、项目内与跨项目链接文字分别符合 §2.1，表达同一内容。
- [ ] 专属文档或任务的编号真实，编号未代替主题；阶段编号有实际内容依据。
- [ ] 新 slug 符合格式并表达主题和用途；日期、修订版本和状态未作为普通区分后缀。
- [ ] 已查找同用途 Site；修订复用原身份和地址，并存理由及限定词有实际含义。
- [ ] 候选名称与实际值分开；维护记录中的 Site ID、slug 与 URL 均有实际来源或明确的未知说明。
- [ ] 发生地址变更时已处理已知链接，并记录旧地址行为的实际核验范围。
- [ ] 维护结果区分已执行、已核验和未验证；文档静态检查未被当作页面或线上变更证据。
