# 原生开发技能执行边界

本文件是技能共用执行说明，不是翻译 preface、审批凭证或自动放行机制。政策正文仍由项目 `AGENTS.md`、`policies/`、`sdd/` 与局部 AGENTS 维护。原生资产在项目根直接维护。命令说明不构成执行记录；服务及宿主证据另行取得。

## 路径与资源

技能中的 `repo:路径` 表示从目标 Git 工作树根解析的文件，不是 URL 或 shell 命令。先用 `git rev-parse --show-toplevel` 固定工作树，不从当前 shell 子目录猜根。

- 正式布局：所有 `repo:` 路径从当前工作树根解析，技能间使用同层相对路径；禁止从旧开发客户端回退读取。
- `src/` 路径是分析目标或接口依据，绝不为资源闭合复制到技能目录。秘密路径只标识禁止边界，不读取正文、不计算摘要。
- 历史 ADR、历史衍生说明不是执行依赖；不存在或尚未实现的工具须标 `UNMET_DEPENDENCY`。不得编造路径、工具名或成功输出。

## 工具与方法

先发现当前会话实际工具。文件读取/搜索使用已提供的文件工具或 `rg`；修改使用当前文件编辑工具；命令使用当前 shell 执行工具。技能名称只用于选择并读取技能，绝不是 shell 命令。

PowerShell 与 Bash 示例保留各自语法；只在对应 shell 已发现时执行。Windows 文件移动/删除用同一 shell 的原生命令，先解析绝对路径并确认属于批准目录。不要跨 shell 拼接破坏性命令。未发现 Bash 时逐条改成 PowerShell 等价操作并核对参数；未经验证的复杂管道停为 `UNMET_DEPENDENCY`，不可机械照抄。

无需个人插件的方法直接执行：TDD = 写失败断言→观察红态→最小修复→绿态重构；诊断 = 最小确定性反馈→可证伪假设→一次一变量→回归；评审 = 读实际 diff→证据定位→按影响排序；计划 = 任务/依赖/验收逐项拆解；文档 = 真实代码核对→模板→反向引用→校验。没有子代理也能在当前任务顺序完成。只有获授权且实际可用才委派子代理，委派不扩大权限。

Git/gh 仅在工具存在、身份与目标确认后使用；认证或网络缺失只阻塞依赖的远端步骤，不打印 token，不借用其他来源 MCP。只读远端结果必须绑定 repo、PR、head SHA 与时间；没有连接证据不声称已验证。

## 授权与硬阻断

1. 业务库只能经 `find_biz_context → list_biz_tables → describe_biz_table → execute_sql`、analyst 只读链路；没有该链路就停。不得用 shell、psql、psycopg、通用 MCP 替代。memory 也不得借用 biz 服务、提升角色或扩大用途。
2. 不打开、打印、记录、传输 `.env`、加密秘密包或真实凭据。缺字段仅使用已审阅脱敏检查接口；解密、口令输入、OS 凭据写入由 Owner 在自己的终端处理，报告只记录状态。不让用户把秘密贴回聊天。
3. SQL guardrail/precheck、runtime skill、Prompt、catalog、冻结契约、memory migration、生产/GRANT/外部镜像、元规则、原生配置和 CI gate 等受保护变更先给具体 diff/影响/恢复来源，停在 `OWNER_APPROVAL_REQUIRED`。
4. commit、push、PR 创建、删除及其他需批准动作保留具体目标的 Owner 决策。聊天批准不等于 hook 自动解锁；原生 hook 对需审批动作保持 block。遇拒绝不得换工具、换编码、改 hook/rules、建 receipt 或改会话模式绕过。执行路线未人工处理时返回 `BLOCKED_EXECUTION_ROUTE`，继续独立只读工作。
5. merge 永远交 Owner 人工处理；评审、check-merge、PR 创建不执行 merge 或 auto-merge。发布评论、回复、issue、定时任务等外部动作须有对应明确授权；草案/建议不等于发送许可。
6. project MCP 仅 GitHub、Playwright、Serena、memory×5，共 8 项；凭据维护工具仅 GitHub+memory×5 的具名变量。biz×5、ssh-manager 和个人/其他来源服务不迁入。

## 调用、委派与返回

- 独立调用：只完成用户请求的本技能范围，输出结果后结束。
- 子任务委派：调用前记录调用者、阶段、子任务、读写目标、可用授权；完成后返回调用者原暂停步骤，不另起阶段。
- 必要同阶段子流程：例如文档校验、范围审查，可以读取同名原生技能并在当前任务执行；这是工作流子调用，不意味着启动子代理或获得外部发布权限。
- 建议/交接：下游技能仅列建议与所需输入。没有明确阶段授权不自动运行；post-merge 不触发提交→推送→PR→收尾循环。
- 所有输出包含：身份/调用模式、实际完成、待批准/缺依赖、证据级别、恢复入口、返回阶段。示例中的勾选、版本、数量均为模板，不得当观测结果。

## 失败、目标变化与重入

每次危险动作前复核绝对路径、分支 tip、PR head、PID 启动时间/命令、compose project/profile/-f 链、volume 或目标内容摘要。任一变化使旧批准不能覆盖新目标，停止该动作并重提差异。

部分完成时按子步骤记录成功/失败/未知，先只读对账再决定剩余动作；已成功步骤不重复。前置失败不盲目进入依赖步骤；仅目标独立、授权仍有效的工作可继续。失败不自动 force、删卷、重建、轮换或回滚。恢复先确认备份/原始内容真实存在，Git 源码不是数据库、volume 或未提交文件备份。

重新进入时读取上次结果并核验当前状态，已满足目标则 no-op 返回；身份不一致或执行结果未知则暂停对应动作。检查器 exit 0、离线 skip、静态合法、Owner 批准、宿主可执行、外部服务可用是不同状态。
