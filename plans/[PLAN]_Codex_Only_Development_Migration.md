## 1. 背景、依据与完成定义

### 1.1 背景

mj-agent 当前以 Claude 开发技能为源，通过 manifest、翻译模板、生成器和 lock 向 Codex 投影部分能力。Codex 已获完整开发参与授权，但其项目资产仍依赖 Claude 源文件、脚本路径及双工具一致性检查。

用户已明确后续由 Codex 开发、Claude 退出、不再保留开发客户端适配器。本次迁移因此需要将技能和配置的维护权交给 Codex 原生文件，并退出旧入口及生成链。

本计划迁移的是开发工具体系。`src/mj_agent/` 中运行的业务 agent、模型 provider、Prompt、SQL guardrail、catalog 和 runtime skill 正文不属于本次改造对象。

## 2. 固定范围及授权边界

### 2.1 本次包含

1. 根与四个局部 AGENTS 入口的必要修订，吸收 CLAUDE 中仍有效的项目说明。

3. `.codex/config.toml`、hooks、rules 转为直接维护；迁出必要 MCP 启动与凭据维护脚本。
4. 退出 Claude→Codex 翻译、投影、生成、adopt、lock、双边比对和专属适配资产。

6. 保留已有安全与离线执行约束；实施独立验收、具名旧资产清理及恢复准备。
7. 仅修复本次迁移造成的回归，或不修就无法满足已定验收的最小配套问题。

### 2.2 明确不包含

- 不改业务 agent、模型/API 供应商、SQL 行为、业务 catalog、Prompt 或 runtime skill 正文。
- 不迁移业务数据库，不改 GRANT、生产 Compose、镜像引用或部署流程。
- 不重构整个 SDD 内核，不为了消除 adapter 这个目录名而搬迁全目录或统一改 schema。
- 不默认承接 #499 剩余实施或 #552 完整修复；不改其他工作树中的既有成果。
- 不建设新的双源生成器、通用适配平台、授权 receipt 系统或全仓诊断平台。
- 不批量重写历史 ADR、计划、归档或证据；不补齐与迁移无关的文档欠账。
- 不安装/卸载全局客户端，不修改用户级信任与个人配置，不读取或复制真实秘密。
- 不因执行某一阶段而自动执行下一阶段、提交、推送、创建 PR、合并或部署。

### 2.3 “不再需要适配器”的精确定义

退出的是 Claude/Codex 双工具兼容机制：source→carrier 翻译、投影、同步、双边能力声明和相应运行依赖。

`sdd/adapters/` 内仍承载 Python、LangChain、Prompt、runtime skill、contract、Docker、BDD/TDD 的项目规范。这些文件本轮保留现址与有效规则；仅修订因开发入口切换而失效的直接引用。目录保留不代表保留双工具适配链。全面重命名目录或 `adapter_coverage` schema 属独立重构，未获授权不实施。

纯客户端适配文件先提取仍有效的开发流程与保护要求，再退役。不得因删除适配文件而丢失规则，也不得把它换个名字继续作为原生文件的生成源。

### 2.4 新发现的处置规则

| 新发现 | 处置 |
|---|---|
| 迁移造成断链、遗漏能力、接口或顺序变化 | 在本次范围内修复并复验 |
| 原定验收必需的直接消费者调整 | 最小修改，登记对应 AC；范围和权限不变时复用已有授权 |
| 基线已有缺陷且迁移未恶化 | 记录现象、基线、影响，留待后续；不顺手修复 |
| 原有问题阻断已定必需验收 | 报告具体阻塞，提出最小处理方案；不自行降低验收标准 |
| 新服务、秘密、部署、业务语义或大范围重构 | 停止对应增量，继续独立工作；需新增范围授权 |

每个增量必须回答：对应哪项 AC？不做会损失哪项原能力？有没有更小的处理方式？答不清前两项就不纳入。

### 2.5 执行授权

- 本文落盘不改变任何现行治理规则；P3 正式切换前，现有生成物禁令仍有效。
- 分阶段提示词只启动指定阶段；读取计划不构成整个迁移、Git 写操作或线上操作的授权。
- 已有授权在目标、动作、关键内容和影响范围不变时复用，不逐文件重复索取。
- 受保护配置、契约、门禁、ADR 状态和批量清理，按现行政策取得对应范围的 Owner 批准。缺授权时先完成清单、差异、验证方案及恢复说明，只暂停依赖该批准的动作。
- 技术权限和业务授权分别判断：Owner 批准不代表当前宿主允许执行；工具失败也不允许绕过规则。

## 4. 分阶段实施

所有阶段串行推进；P1/P2 可在内部按独立资产分组工作，但阶段边界不能越过。每个交付单元同时包含相关资产、直接消费者和验证，避免先删门禁、后补保护。阶段不强制等于一个 PR。

### 5.1 安全不变量

安全约束分为政策、宿主权限、hooks/rules、凭据权限、CI 和人工审查等不同层。必须说明每条由哪一层承担及其边界；不承诺所有政策都能由命令前缀规则或 hook 强制。

## 6. 验证与验收标准

### 6.1 验证分层

| 层次 | 必需证据 | 不证明的事项 |
|---|---|---|
| L1 来源完整性 | 37 技能、依赖与消费者逐项处置，新增/删除可追溯 | 实际服务可连接 |
| L2 原生独立性 | 排除旧客户端的独立副本、原生结构与路径检查通过 | 凭据或网络就绪 |
| L3 确定性行为 | 正例、拒绝、缺失、解析失败、恢复及安全断言 | 所有宿主真实激活 |
| L4 流程语义 | 37 项八维对照、正反例与高影响恢复场景 | 模型自动选择准确率 |
| L5 真实 Codex 宿主 | 实际指令/技能发现，规则和 hook 的无秘密 canary 证据 | 未测环境或服务业务成功 |

L1–L5 是本计划技术迁移必需验收。L6 只有在明确纳入范围后才成为必需；未执行时写“未验证”，不得声称全部运行能力通过。若用户后来要求完整线上可用，须先更新验收范围，而不是在失败后改口径。

### 6.2 必要测试场景

| 主题 | 正向场景 | 反向/恢复场景 |
|---|---|---|
| 技能资源 | 37 项可发现、必要相对链接可达 | 缺 SKILL、名字不一致、缺引用、仍调用旧路径 |
| 调用边界 | 独立调用和委派返回正确 | PR 后自动合并、审查自动发布、重复收尾被识别 |
| MCP 配置 | 原生结构有效、仅允许服务、变量按名转交 | config 缺失/非法、禁入或未知服务、凭据字面量被拒绝 |
| 启动器 | 根/子目录/空格路径/worktree 定位正确 | 缺变量脱敏失败、错误根目录不回退旧客户端 |
| 原生保护 | 普通允许、绝对禁止、需审批三类清楚 | 有效会话不支持审批时准确报不可用；不伪称已获批准 |
| 特殊路径 | 保护路径、绝对路径及实际工具 payload 处理符合声明 | 不支持或未知输入有明确能力说明；不声称全覆盖 |
| 离线执行 | 继承已有受控 runner 和关键安全断言 | 外部依赖、用户环境泄漏、非预期插件/文件输入 |
| 清理恢复 | 精确清单可恢复到已知来源 | 文件身份变化、个人文件、不属于目标目录的路径停止 |

真实宿主至少覆盖：全部技能目录被识别；五个技能族各一项无副作用显式调用；一个近邻误触发场景；Git 受控动作、受保护文件和删除场景的无真实副作用演练；原生 hook/rule 至少一个允许及一个拒绝分支。检测动作不能真的推送、删除业务文件、写库或读取秘密。证据说明实际执行与静态推演的区别，不让模型生成“预期输出”代替观测。

Windows 为已知开发宿主；Linux CI 对代码、文档和检查器进行实际验证。当前 Windows launcher 的 Linux 运行支持不作为自动新增需求。P0 如确认需要跨平台 MCP 启动，再明确列入范围、实现及实际测试，不能仅靠静态语法检查宣布支持。

### 7.2 分阶段恢复

- P0–P2：正式入口未切换；只按清单清理或调整迁移自己的候选，保留原有用户修改。
- P3：记录成组切换基线及新文件集合。需要恢复时将入口、来源声明、配置、守卫和 CI 一起恢复；不能只恢复配置却保留新门禁。
- P4：隔离副本可重新构建；不通过重置原工作树来清理测试环境。失败的原始证据保留。
- P5：每个已删除共享文件有基线 SHA/来源；保留文档中的历史定位，不为恢复建立第二份活动技能源。
- 已提交或共享的变更：采用正常评审回退流程，未明确授权不强推、不 reset 共享历史。
- 代码恢复不等于 OS 凭据、容器、部署或数据库恢复；这些副作用不在默认迁移内，若另获批准执行，必须另有恢复步骤。

### 7.3 必要决策点

1. P0 固定目标平台、资产集合、必需验收和工作树安排。
2. P3 前审阅定向 ADR、受保护文件/契约、所有权及门禁切换差异。现有授权覆盖则直接复用。
3. P5 前审阅可执行的逐文件清理和恢复清单；不要求 Owner 批准尚未形成的笼统删除范围。
4. P6 对 commit、push、PR、merge 等分别按已有明确授权处理。

这些是未来执行边界，不要求用户为了当前计划文档再进行一次批准。
