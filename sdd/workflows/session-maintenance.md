# Workflow: 会话维护

本规则由根 [AGENTS.md](../../AGENTS.md) 按需引入，统一维护 Codex 开发协作会话的归档摘要、推荐标题与明确请求的客户端任务重命名。客户端动作按当次实际工具能力执行。

来源参考：mj-system 的 `.agents/references/session-maintenance.md`（提交 `3e55613`）。本文件在 mj-agent 独立维护，执行与授权语义引用本项目 kernel，不依赖上游文件。

## 1 触发与输出

按语义识别明确请求及同义表达：

- “归档本次对话”“整理本次 session”等：只输出一个标题和精简摘要，使用下方归档模板，不自动改名或执行客户端归档。
- “给本次对话命名”“推荐当前对话标题”等：只输出一个推荐标题，不附说明或候选列表。
- “将当前任务重命名为……”等明确改名请求：按用户指定的完整标题原文执行客户端重命名，不擅自添加日期、编号、压缩或改写。
- “按项目规范重命名当前任务”等：依据下方标题和日期规则生成一个标题，并执行客户端重命名。

引用、示例、否定、讨论机制或询问可行性不触发。“PR 合并后收尾”“归档文件”等按实际对象和项目原有流程处理；对象确实不明且影响动作时再澄清。实施或修改本机制的请求及其中引用的示例，不属于实际归档或重命名请求。

明确的重命名请求即为该动作的授权；目标和内容已明确，或已要求按规范生成时，不重复确认。实际执行与结果报告遵循 §6。

## 2 标题

以下规则适用于推荐标题、归档标题及按项目规范生成的重命名标题；用户明确指定完整标题时采用原文，不套用生成规则。I 表示 Issue，P 表示 PR，按已知关联生成：

| 已知关联 | 标题格式 |
|---|---|
| Issue 和 PR | `MMDD-I123-P456-对象任务` |
| 仅 Issue | `MMDD-I123-对象任务` |
| 仅 PR | `MMDD-P456-对象任务` |
| 两者均无 | `MMDD-对象任务` |

只使用本次对话中已明确或已核实属于本仓库、本任务的编号。上表的 123、456 仅为格式示例，不是本任务编号。不猜编号，不从任意数字推断关联，不为补齐标题额外搜索或创建 Issue、PR；有歧义时省略。

多个关联对象时，标题最多保留一个主要 Issue 和一个主要 PR，其余在必要时写入正文；主要关联不明确时省略对应编号。编号不表示已关闭、已合并或已完成。

对象任务使用简短中文描述，优先 6–10 个汉字，约 8 个字为宜，尽量不超过 12 个字。长度建议只针对“对象任务”，不包含日期、Issue/PR 编号和分隔符。采用“核心对象＋具体动作”，将最有辨识度的信息放在前面；不添加活动分类、阶段编号、完成状态或候选标题列表。

保留必要的技术缩写，以清楚辨识为先，不机械凑字或截断。上述范围是推荐长度，不作为硬性校验门槛，也不保证所有移动端完整显示。

格式示例：`0916-I123-P456-会话归档规则`、`0916-I123-P456-工具错误处理`。示例日期和编号不代表当前日期或真实关联。

## 3 日期

按规范生成标题时，用户指定日期或时区优先，否则采用当前会话明确时区的归档当天；时区缺失时采用 Asia/Taipei。推荐标题或按规范重命名也使用同一日期规则，以命名当天为准；完整指定标题不改写其中日期。

标题日期为 MMDD，记录日期为 YYYY-MM-DD。跨日会话按归档当天生成，不改写历史成果日期，不自动重命名旧对话。

## 4 归档模板

```text
标题：按上述规则生成
日期：YYYY-MM-DD

成果：实际完成了什么，以及必要的验证结果。
结论：本次确定了什么。
待办：尚未完成的事项，以及下一步从哪里继续。
```

成果、结论、待办各用一至三句话，无内容写“无”“尚未形成”或“暂无明确后续动作”。不添加前言、重复结语、关键词、分类标签或其他固定元信息。

## 5 事实与继续工作信息

只依据本次可获取的对话和已核实成果，区分讨论、建议、接受、写入、测试、提交、合并及部署。不能将计划写成已完成成果，不能将静态检查通过写成业务运行成功，也不能将其他任务的成果计入本次。

必要时注明验证对应的 SHA、环境、批次或时点；不为填模板重新跑测试或查询服务。上下文不全时，在末尾简短说明覆盖范围。

不新增独立交接模式。只有影响继续工作时，才在成果或待办中保留工作树、分支、未提交修改、相关文件、目标环境、首个未完成步骤、已有授权范围或恢复条件。

发生过运维副作用时，必要的复位状态和在途批次不能为追求简短而省略。执行、恢复与授权语义复用 [执行闭环](execution-loop.md) 和 [AI 协作边界](../../policies/ai-agent.md)，不建立第二套流程。不得包含凭据、完整环境变量或未脱敏工具输出；摘要不授权绕过项目数据边界去补查信息。

## 6 动作边界

默认只回复文字，不保存或移动文件、不更新项目状态、不执行 Git 或运维动作、不修改客户端标题、不归档客户端任务。普通对话摘要与推荐标题不作为项目 canonical 或 working 文档落盘，原任务已有的记录义务继续适用。

明确要求额外动作时，按请求范围、项目规则、已有授权及可用工具执行，分别核实实际结果。推荐标题不等于已改名，文字摘要不等于已保存，生成归档记录不等于客户端任务已归档。明确要求客户端归档时只操作已确定且获授权的目标，并核实实际归档结果；与 [项目文档归档](../../policies/archive.md) 分别处理。

明确重命名时：

1. 确定目标与最终标题。当前任务使用工具提供的当前任务目标语义，不猜任务 ID；其他任务仅在用户明确指定且已核实目标时操作，不批量重命名历史任务。
2. 调用当前可用的客户端重命名功能。若本次工具列表提供 `mcp__codex_app__set_thread_title`，按其接口传入 `title`；修改当前任务时省略 `threadId`。工具名称及参数以本次实际能力为准，不以文档中的名称假定能力已连接。
3. 检查实际返回是否确认目标标题已修改；只有成功得到确认后才能报告“已重命名”，并给出实际标题。失败、报错或返回未能确认成功时不能只凭调用完成报成功；结果不确定时优先只读核实，不盲目重复改名。
4. 能力不可用、执行失败或结果仍无法确认时，如实说明“未执行”“失败”或“结果未确认”，并给出可手动使用的标题。用户指定的完整标题仍保留原文。

验证本机制时，静态规则检查与客户端实际重命名验证分别记录；实际验证仅针对获授权的测试任务。工具接口存在、静态场景通过均不代表实际修改成功。
