## §4 Observations

1. **SUT-spec drift on keyword count**: `spec.yml` REQ-001 statement claims "blocks 14 dangerous keywords"; actual `_BLOCKED` regex at `guardrail.py:36-40` enumerates **16 keywords** (`INSERT / UPDATE / DELETE / DROP / TRUNCATE / ALTER / GRANT / REVOKE / CREATE / COPY / VACUUM / REINDEX / CLUSTER / ANALYZE / LOCK / CALL`) plus separate **SET SESSION** pattern (17 total surface). M5+ reconcile candidate (either bump spec count or document SET SESSION as separate special case).
2. **Test coverage gap on 7 regex keywords + SET SESSION**: only 9 of 16 keywords have direct parametrize entries; `REVOKE / CREATE / COPY / REINDEX / CLUSTER / ANALYZE / LOCK` + `SET SESSION` covered by regex pattern but lack explicit test cases. Coverage = 9/17 = 53% empirical / 100% via regex compilation.
3. **Trailing semicolon handled idempotently**: `TestAccepted.test_trailing_semicolon_allowed` confirms `guardrail.py:71-72` single-trailing-`;` strip; multi-statement detection at L73-74 fires only on inner `;`.
4. **Per-table allowlist backward compatibility preserved**: `TestTableLevelAllowlist.test_no_per_schema_map_defaults_to_wildcard` confirms absent `allowed_tables_per_schema` map → schema-level wildcard behavior (per `guardrail.py:103` `if s_lower in table_whitelist` conditional).
5. **biz_dws unrestricted by design**: `TestTableLevelAllowlist.test_dws_unrestricted` confirms biz_dws schema wildcard preserved (per mj-system contract: biz_dws is fully exposed; biz_dwd is restricted to 2 dim tables per `policies/data-boundary.md`).
